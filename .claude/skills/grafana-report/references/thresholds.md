# メトリクス閾値リファレンス

## KPI 閾値定義

| メトリクス | 算出式 | Good | Warning | Problem |
|---|---|---|---|---|
| セッションあたりコスト | `total_cost_usd / total_sessions` | < $8 | $8 -- $15 | > $15 |
| キャッシュヒット率 | `cache_read / (input + cache_read)` | >= 95% | 80 -- 95% | < 80% |
| 出力/入力トークン比 | `output_tokens / input_tokens` | < 5 | 5 -- 10 | > 10 |
| ツールエラー率 | `tool_errors / tool_calls` | < 5% | 5 -- 10% | > 10% |
| 圧縮イベント/セッション | `compression_events / sessions` | < 0.2 | 0.2 -- 0.5 | > 0.5 |
| コスト/ツール呼び出し | `total_cost_usd / tool_calls` | < $0.05 | $0.05 -- $0.20 | > $0.20 |

## 各指標の解釈

### セッションあたりコストが高い

セッションが長くなりすぎているか、試行錯誤が多い。

**原因の可能性:**
- 事前設計なしで実装に着手している
- タスクが大きすぎて1セッションに詰め込んでいる
- キャッシュが効いていない（新規セッション開始が多い）

**改善アクション:**
- `claude --resume` でセッションを継続し、キャッシュを再利用
- 実装前に Plan エージェントで設計を固める
- タスクを小さく分割して個別セッションで処理

### キャッシュヒット率が低い

新規セッションの開始が頻繁で、キャッシュが活用されていない。

**原因の可能性:**
- 毎回 `claude` で新規セッションを開始している
- 短いセッションを多数作成している

**改善アクション:**
- `--resume` で前セッションを継続（同じプロジェクトの場合）
- `--continue` で直近セッションの会話を引き継ぐ
- 関連タスクはまとめて1セッションで処理

### 出力/入力トークン比が高い

Claude の応答が冗長になっている。

**原因の可能性:**
- プロンプトに簡潔さの制約がない
- コード生成で不要な説明が多い
- サブエージェントの出力が制御されていない

**改善アクション:**
- CLAUDE.md に「簡潔に応答する」指示を追加
- サブエージェントに出力フォーマット制約を設ける
- 必要な出力形式を明示的に指定する

### ツールエラー率が高い

ファイル探索やコマンド実行の試行錯誤が多い。

**原因の可能性:**
- Grep/Glob のパターンが不正確
- 存在しないファイルへのアクセス
- Bash コマンドの実行エラー

**改善アクション:**
- ファイル探索で 2〜3 回失敗したら `Agent(Explore)` に委ねる
- Grep/Glob の使い方を CLAUDE.md で明確化
- よく使うパスやパターンをスキルに組み込む

### 圧縮イベントが多い

セッションが長くなりすぎてコンテキストウィンドウの圧縮が発生している。

**原因の可能性:**
- 1セッションに多くのタスクを詰め込んでいる
- 巨大なファイルを読み込んでいる
- 会話履歴が膨大

**改善アクション:**
- タスクを適切に分割する
- `--resume` で新しいコンテキストから再開
- 大きなファイルは部分的に読み込む（Read の offset/limit を活用）

### コスト/ツール呼び出しが高い

各ツール呼び出しのコストが高く、無駄な呼び出しが多い可能性がある。

**原因の可能性:**
- 同じファイルを繰り返し読み込んでいる
- 広範囲の探索を手動で繰り返している
- 不要な Bash コマンド実行

**改善アクション:**
- 広範囲の探索は Agent に委譲
- Read で必要な部分だけ読み込む
- Bash の代わりに専用ツール（Grep, Glob）を使用

## トレンド分析の基準

### 急変の検出

| 指標 | 急変の定義 |
|---|---|
| 日次コスト | 前日比 2 倍以上の増加 |
| ツールエラー率 | 日次で 10% を超過 |
| セッション数 | 期間平均の 2 倍以上 |

### 傾向判定

- **改善傾向**: 期間後半のメトリクスが前半より良化
- **悪化傾向**: 期間後半のメトリクスが前半より悪化
- **安定**: 大きな変動なし

## 重要な注意点

- 絶対値より **前回比・傾向** を重視する
- データが少ない場合（セッション数 < 5）は閾値判定の信頼度が低いことを明記する
- プロジェクト間のコスト差は作業内容の違いを反映するため、単純比較は避ける
